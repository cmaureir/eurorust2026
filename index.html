Part twoThe C++ safety crisis

C++ has been looking for Rust
for a long time

2011–14
"Modern C++": RAII everywhere, smart pointers, auto, move semantics
2015
C++ Core Guidelines + GSL (Stroustrup & Sutter, CppCon)
2015–19
The Lifetime Profile: static analysis to catch dangling references. Never fully delivered.
2019–22
Sanitizers, hardened standard libraries, -fbounds-safety

Why "just be careful" doesn't scale


std::vector<int> v{1, 2, 3};
int& r = v[0];

v.push_back(4);   // may reallocate

r = 42;           // use after free

Compiles clean. No warning.


let mut v = vec![1, 2, 3];
let r = &mut v[0];

v.push(4);        // second borrow

*r = 42;

error[E0499]: cannot borrow v as mutable more than once

The difference isn't the bug. It's who is responsible for finding it.

C++'s three answers

Profiles

  • Stroustrup, Sutter
  • Opt-in enforcement of subsets: bounds, type, lifetime
  • No new syntax, no new stdlib
  • Currently the committee's chosen direction

Safe C++ / Circle

  • Sean Baxter (P3390)
  • A real borrow checker: ^ borrows, safe functions
  • Needs a second standard library (std2)
  • Not adopted

Carbon

  • Google, 2022
  • A successor language, not a dialect
  • Bidirectional C++ interop as the whole point
  • Explicitly "if Rust works for you, use Rust"

The lesson Rust should take

  • Nobody is rewriting 30 million lines of C++. Ever.
  • So the realistic outcome is not migration, it is a permanent border
  • Which makes interop the product, not a nice-to-have
  • Every hour spent on cxx, bindgen, crubit, ABI and build integration is worth more than another language feature

The Rust Foundation's Interop Initiative (2024, seeded with $1M from Google)

How Python got fast, for 30 years


static PyObject* hello(PyObject* self, PyObject* args) {
    char *msg = "Hello EuroRust 2026!";

static PyMethodDef functions[] = {

Manual reference counting. Manual error propagation.
One missed Py_DECREF away from a leak, one extra away from a crash.

How Python gets fast now


use pyo3::prelude::*;

#[pyfunction]
fn hello() -> &'static str {
    "Hello EuroRust 2026!"
}

#[pymodule]
fn demo(m: &Bound<'_, PyModule>) -> PyResult<()> {
    m.add_function(wrap_pyfunction!(hello, m)?)
}
  

maturin develop   # builds it, installs it into the venv, done

The refcounts are the Bound<'_, T> lifetime. Errors are PyResult. The module table is generated.

Python is already running on Rust

ruff uv pydantic-core polars tokenizers safetensors tiktoken cryptography orjson rpds-py* watchfiles deltalake granian blake3 ty

If you pip install almost anything in the data or AI stack today,
you are downloading Rust binaries.

Most Python developers have no idea. That's the point - it worked.

rpds-py is a dependency of jsonschema, which is a dependency of half of PyPI. Nobody chose it. It just arrived.

Why Rust, and not C++?

  • Distribution. One maturin command against a matrix of wheels beats a decade of manylinux pain
  • No build system negotiation. Cargo already knows how to find your dependencies
  • Fearless concurrency in a language whose users have never been allowed to have any
  • A safety story you can put in a security questionnaire

The bill for this

  • Platform support. Python ran on s390x, AIX, HPPA, obscure BSDs. Rust does not, or not at tier 1.
  • Bootstrapping. Distros that build everything from source now need a Rust toolchain to build a TLS library.
  • Two ecosystems of dependencies in one artifact, and one SBOM that has to describe both.
  • Maintainer skill gap. Your Python library now needs someone who can review unsafe.

when your crate becomes a transitive dependency of half of PyPI, you have inherited users who never chose Rust and cannot debug it. What do you owe them?

Part fourThe relationship goes
both ways

How influence actually travels

  1. Code. Rust is literally inside their runtimes. A crate becomes a transitive dependency and the argument is over.
  2. Design. Ideas escape the language. Result → std::expected. Cargo → uv. Borrowing → Swift, Mojo, Hylo.
  3. Politics. Rust made "safety is the compiler's job" a position institutions could adopt. Carbon and Circle are answers to a question Rust asked.

Every newcomer arrives
with expectations

And a large enough group of newcomers
doesn't adapt to a language.
It changes it.

What they bring with them

From C++

  • "Where is the standard?" → the spec effort, Ferrocene
  • "Where is the stable ABI?" → crABI, extern "C" everywhere
  • "It has to build in CMake / Bazel" → Corrosion, cargo-as-a-library
  • Compile-time everything: const generics, const traits
  • Certification, MISRA-shaped rules, qualified toolchains
  • Custom allocators, placement, fallible allocation

From Python

  • "Why are there three ways to do this?"
  • Expectation of batteries, and of one obvious crate
  • Docs as a first-class deliverable, not a README
  • A fast edit-run loop; frustration with compile times
  • Error messages that teach rather than accuse
  • Explicit, enforced community norms

And Rust exports too

Into C++

  • std::optional, std::expected, std::span
  • Hardened stdlib, bounds profiles
  • The entire premise that safety is the compiler's job
  • Carbon and Circle would not exist without Rust

Into Python

  • uv is openly "Cargo, for Python"
  • Lockfiles, a resolver you can trust, one tool
  • ruff's diagnostics look like rustc's on purpose
  • Rising expectations for error message quality across the board

Elsewhere: Swift's noncopyable types, Mojo, Hylo, Zig's allocator discipline.

Rust is filling gaps neither
of them can close

  • C++ cannot get memory safety without breaking compatibility - and compatibility is the reason people still use it
  • Python cannot get performance without leaving Python - the C API is a 30-year-old contract nobody can afford to break
  • Rust is the only place where both of those problems have the same answer

Part fiveWhat to watch

Five things, on your radar

  1. Does C++ ship credible Profiles? If yes, the political argument for Rust weakens overnight, and interop matters more than ever. If no, the regulatory pressure lands on Rust's side.
  2. Regulation with dates on it. The EU CRA's 2027 obligations mean SBOMs, vulnerability reporting and provenance become crates.io problems, not somebody else's.
  3. Free-threaded Python. No GIL means PyO3 has to answer real concurrency questions - and Rust is the best-positioned language in that room.
  4. Build system convergence. Cargo is wonderful and it is not what Bazel, CMake, Yocto or Debian want. Somebody has to blink.
  5. Supply chain. cargo-vet, cargo-crev, RustSec, namespaces. Being the trusted ecosystem is now a competitive feature.

And two you can't schedule

  • Who pays for this? Foundation funding, maintainer burnout, and a dependency graph that a lot of critical infrastructure now sits on top of.
  • The newcomer wave itself. Every C++ team told to write a memory safe roadmap, and every Python library that needs a fast core, sends people here. Ready or not.

The Rust community is
becoming heterogeneous

Kernel people. Automotive people. Web people.
Data scientists who have never seen a segfault.

That is not dilution. That's what winning looks like -
and it is much harder to run than a small community.

Last words

  • Rust doesn't evolve in isolation
  • Memory safety is now a political and institutional concern, not a language design debate
  • Python is already running on Rust - most of its users don't know it
  • The world runs on C++ - and Rust has the solutions to improve it.
  • The influence is bidirectional
  • Rust fills gaps neither C++ nor Python can fully close
  • Staying heterogeneous is the hard part, and the whole point

Look at your neighbours.

They are already looking at you.
